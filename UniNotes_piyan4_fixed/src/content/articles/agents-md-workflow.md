# 用 AGENTS.md 建立可持續協作的 AI 專案

使用 AI 寫出第一個網頁只是開始。當專案逐漸增加頁面與內容，如果每次都重新解釋風格、檔案位置與程式規則，很容易讓成果變得不一致。`AGENTS.md` 可以把這些共識整理成一份長期使用的專案手冊。

## AGENTS.md 是什麼

`AGENTS.md` 是放在專案中的 Markdown 指引文件，用來告訴 AI 助手這個專案的目的、技術選擇、資料夾用途、命名方式、開發流程與限制。它不是程式碼，也不會自動替你完成開發；它的價值在於讓每次任務都有共同依據。

## 建議包含哪些規則

### 專案目的與使用對象

先說明網站要解決什麼問題、主要讀者是誰，以及內容範圍。目標越具體，AI 越容易判斷哪些內容適合加入。

### 檔案結構與責任

列出重要資料夾及檔案用途，例如文章統一放在 `src/content/articles/`，共用元件放在 `src/components/`。這能降低 AI 把內容放錯位置或重複建立元件的機率。

### 格式與設計規範

定義文章 Frontmatter 欄位、標題層級、檔名格式、色彩、排版與手機版要求。最好提供一份可直接複製的範例，而不是只寫「保持一致」。

### 測試與完成條件

明確列出建置指令、需要檢查的頁面與部署方式。AI 應回報實際測試結果，不能把尚未執行的測試說成成功。

## 在 UniNotes 中如何使用

UniNotes 將文章內容與頁面模板分開。要新增一般知識文章時，只需在 `src/content/articles/` 新增符合規格的 Markdown 檔案；Astro 會依照既有集合設定產生文章頁，首頁、分類頁與搜尋頁也會讀取同一份文章資料。

例如可以對 AI 下達以下任務：

```text
請先閱讀 AGENTS.md，依照文章格式新增一篇
「GitHub Pages 部署入門」，放在正確分類，
完成後執行 npm run build 並回報結果。
```

## 小結

好的專案規則不是限制創意，而是把重複溝通的成本降低。當目標、結構、格式與測試方式都被清楚記錄，AI 就能把注意力放在新內容本身，讓專案以一致的方式持續成長。
